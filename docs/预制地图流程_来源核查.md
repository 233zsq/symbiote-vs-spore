# 预制地图流程：来源核查

核实日期：2026-10-14。对象：Minecraft Java 1.20.1 / Forge 47.4.23 整合包。

**状态：可行性提案，未实装、未游戏验证。** 本文核实工具能力与版本声明，不代表批准替换现有地形、放开 worldgen 冻结或恢复 FTB 任务施工；本轮不开 Minecraft。现行边界见 [资料入口](README.md) 与 [通用规则](交接启动词_通用规则.md)。

## 结论

“固定地图承载主线地标，原生世界生成提供地形与探索内容”方向可行。原方案需要修正三点：先核实现有地形组合，禁生成规则应在预生成前确定，复制建筑不能直接视为完整的模组结构。建议先做有限区域和少量主线地标的小样，通过结构功能与存档复制验收后再扩大范围。以下均是制作建议，尚未执行。

## 2. 固定位置：生成规则、完整结构、建筑模板应分开

- `worldgen/structure_set` 管结构候选与分布。Java 1.20.1 原版 placement 类型为 `random_spread` 和 `concentric_rings`，不能把这类 JSON 当成任意绝对坐标清单。生物群系条件属于结构及相关标签配置；`placed_feature` 管配置特征的放置，与完整结构注册不是同一条链路。固定 seed 可固定给定规则下的结果，不等于指定任意 `(x,y,z)`。[1.20.1 placement API](https://maven.fabricmc.net/docs/yarn-1.20.1%2Bbuild.8/net/minecraft/world/gen/chunk/placement/StructurePlacementType.html)、[Forge 注册表文档](https://docs.minecraftforge.net/en/latest/datagen/server/datapackregistries/)
- `/place structure <id> [pos]` 调用已注册结构的生成逻辑；`pos` 是生成原点，具体地形高度、布局与生成条件仍取决于结构实现。`/place template <id> [pos] ...` 相当于结构方块加载模板，适合明确的建筑块数据；`/place jigsaw` 从模板池展开。三者不能互相替代。[Mojang 命令定义](https://feedback.minecraft.net/hc/en-us/articles/6731464524941-Minecraft-Java-Edition-1-19)
- **工程推论，待游戏验证：** 结构方块或 WorldEdit 搬来的外观，不能作为 `/locate`、Explorer's Compass、结构范围刷怪、Boss 激活及任务检测的通过证据；`/place structure` 也不能免除这些验收。复杂模组可能还有存档状态、触发器和自定义生成副作用，应逐结构记录并复测。
- 不建议先把所有结构放进高频区块生成回调。若后续确需自动布置，另行设计服务端的一次性执行、区块加载范围、失败记录与重试机制；这是待设计项，本轮未核验 KubeJS 的具体事件 API。

**顺序修正：** 在预生成之前确定哪些结构继续自然生成、哪些只保留主线定点版本。预生成完成后再禁生成，只影响后续生成，不能移除已写入区块的建筑；Chunky 负责预生成，并不天然提供结构过滤。[Chunky 项目说明](https://github.com/pop4959/Chunky)

## 3. WorldPainter 与外部编辑器的实际边界

| 工具 / 原方案说法 | 核实与建议 |
|---|---|
| WorldPainter 导入现有世界后再导出 | 官方明确它是地图生成器，对现有世界只提供有限 Import / Merge 支持。Import 主要读地形高度、表层及群系，不把建筑、洞穴、树木等都变为可编辑对象；回写原图须用 **Merge**。直接 Export 是重新生成世界，不能理解为完整保真往返。改变坡度可能损坏建筑，默认只读区块是保护措施。[官方 FAQ](https://www.worldpainter.net/trac/wiki/FAQ) |
| “只导出地形，让模组补矿石与结构” | Populate 的现代支持不能一概否定：官方当前说明 1.18+ 可请求 Minecraft 后续填充；但具体矿物、植被和结构由版本、群系和生成实现决定，官方尤其说明结构是否生成随版本变化。它不是对所有模组结构的保证，也不能让 Minecraft 重跑 WorldPainter 已完成的基础地形阶段；叠加 Resources / 树木层可能重复生成。[官方 Populate 文档](https://www.worldpainter.net/trac/wiki/Populate) |
| Amulet 跨版本直接搬模组场景 | 官方 FAQ 表示模组世界测试有限，只建议备份后尝试，并称 1.13+ 较有希望。不能将“支持打开版本”扩写成模组方块、方块实体、实体、物品及跨版本注册名均保真。先在同版本、同模组组合的副本中验证箱子、刷怪笼与自定义方块状态，再考虑跨版本。[官方 FAQ](https://www.amuletmc.com/faq) |
| Forge 包内安装 FAWE | FAWE 官方发行页平台为 Bukkit / Paper / Purpur / Spigot，安装文档要求放 `plugins`。源码存在 Forge 相关目录不能证明有可直接安装的 Forge 1.20.1 官方发行。对本包应优先评估版本匹配的原生 WorldEdit Forge 构建；不因此引入混合服务端。[FAWE 发布平台](https://modrinth.com/plugin/fastasyncworldedit)、[FAWE 安装](https://intellectualsites.gitbook.io/fastasyncworldedit/getting-started/installation)、[WorldEdit 安装文档](https://worldedit.enginehub.org/en/latest/install/) |
| Default World Type 自动复制存档模板 | 作者定义是修改创建新世界时默认选中的 **世界类型**，不是复制完整存档。发布预设世界需要单独验证存档导入或模板复制机制，不能仅安装此 mod 后宣称已实现。[作者说明](https://www.curseforge.com/minecraft/mc-mods/defaultworldtype) |

因此，**现有复杂模组世界宜以游戏原生生成和游戏内修饰为首选流程**；WorldPainter 更适合作为另行制作地形底图的候选。若确需对现有世界 Merge，只选择副本和局部区域，并验收树木、洞穴、模组方块与结构功能。这是根据工具边界作出的工程建议，尚未在本包执行。

## 4. 规模、真实地形与外来场景

- 20,000 × 20,000 格约为 1,562,500 个区块（计算值，不含外围及其他维度）。耗时、空间与内存须由小样测量，不能预先承诺；先做 2,048–4,096 格区域更便于验证。
- DEM 流程可用，但 SRTM 不是全球任意地区覆盖：主要为北纬 60° 至南纬 56°，约覆盖全球 80% 陆地。OpenTopography 提供多种全球 / 区域数据，应按目标地点、分辨率与访问条件选择。[USGS SRTM 资料](https://pubs.usgs.gov/fs/2005/3068/report.pdf)、[OpenTopography API](https://portal.opentopography.org/apidocs/)
- Java 1.20.1 默认主世界可放置方块的 Y 为 `-64…319`，总高 **384**；319 是最高方块坐标，384 是跨度，不能写成两个可任选的高度上限。Mojang 1.18 说明增加上下各 64 格、总高 384。[Mojang 高度变更](https://www.minecraft.net/en-us/article/caves---cliffs--part-ii-out-today-java)
- 地理 DEM 需先选范围并处理投影、无数据值、像素尺度和高程映射，再转换为 WorldPainter 可读取的高度图；不要把 GeoTIFF 的地理元数据当成自动采用的 Minecraft 比例尺。[WorldPainter 高度图 API](https://www.worldpainter.net/trac/wiki/Scripting/API)
- 其他游戏的模型提取、体素化、BuildTheEarth / Arnis 路线及素材授权本次未逐工具验证，暂作独立预研项；不作为当前主线地图制作的前置条件。

## 6. 建议的小样流水线

以下是待采纳的制作顺序，不是本轮已执行内容，也不预定 Boss 主线人选。

1. **先画路线和场地需求。** 选 2,048–4,096 格区域，安排一个出生村、一处共生体陨石和 2–3 类候选战斗场地；检查移动距离、岔路、退路及 EF 战斗空间。结构样本是技术验证对象，不等于剧情名单定稿。
2. **核实并冻结地形组合。** 确定精确文件、数据包优先级、seed、出生点、地图边界或区域外延展方式；在新制图副本中验证，不在旧正式存档中途换生成器。
3. **在创建与预生成前确定随机结构政策。** 只禁计划定点化的目标，保留需要的矿物、生态和背景探索内容。已有合适的自然地标可以直接纳入路线，减少搬移造成的状态缺失。
4. **小范围原生生成，再布置主线地标。** 优先复用自然结构；需要搬放的逐项选择 `/place structure` 或模板，并记录实际高度、朝向、尺寸、来源和触发需求。大型结构不能只登记一个坐标。
5. **游戏内修饰道路和战斗空间。** 为 Boss 留出平整场地、活动高度、出生与脱战空间，再修山体衔接、洞口、河岸和视觉引导；DEM 或外来场景只作为后续独立素材路线。WorldPainter 不作为复杂模组世界的常规整图往返工具。
6. **通过玩法与复制验收后再扩图。** 验证导航、Boss、奖励、任务条件、围城及感染机制对场景的影响；另做新档模板复制测试。区分地图必需初始状态与制作者测试进度，按各模组的存储方式制定清理规则，避免直接整删存档 `data/`。

规模计算：2,048² 格为 16,384 个区块，4,096² 格为 65,536 个区块；20,000² 格为 1,562,500 个区块，分别约为两者的 95.4 倍和 23.8 倍。先证明一段流程能完整游玩，再测量扩图成本。

## 7. 后续验收边界

以下事项须在用户允许恢复相关制作后，在隔离副本中完成：

1. 确认现有 Epic Terrain Configured + Terralith 的实际资源覆盖与新世界表现。
2. 选择少量主线结构，对比自然生成、`/place structure` 与模板粘贴的结果，分别验收外观、战斗 / 奖励触发、结构定位与任务检测。
3. 对涉及外部编辑的局部区域，验证方块实体、容器、实体和相关存档状态；不能只截图建筑。
4. 验证新存档复制、出生位置、主线状态复位与区域外继续生成的行为，再决定地图大小及发布方式。

来源只能确认工具声明和已读文件，不能代替这些本包行为验收。
