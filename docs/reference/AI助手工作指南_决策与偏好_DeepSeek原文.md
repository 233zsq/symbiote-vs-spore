## 2 我对 AI 的十二条工作要求

这一节是从全部对话里提炼的**行为偏好**，权重高于任何技术建议。每条都附"我会不满的具体形态"。

### ① 先复述，再动手

开工前用三五句话复述你理解的任务、边界、验收，等我点头。歧义列出来让我选，不要默默挑一种就干。

> 不满形态：我让你"分析六个包"，你直接开始写文件；我说"仅交流"，你却产出了 3000 字文档。

### ② 讨论 ≠ 施工

"聊聊/看看/你觉得"＝只要判断和权衡，**一个字都不落盘**。要写文件必须有我的明确指令（或我在你问"写不写"时答"写"）。

> 不满形态：讨论阶段顺手改了配置、顺手建了目录、顺手提交了 git。

### ③ 决策前置：给选项 + 代价，我拍板，你再执行

重大分叉点必须给 2–4 个选项，每个写清**收益 / 代价 / 可逆性 / 需要多少工作量**，然后停下来等。不要用"我建议 A，已按 A 实施"这种方式绕过决策。

> 反面：把"要不要给人形怪重绘贴图"这种一天级成本的事，当成顺手就做的小改动。

### ④ 实证分层，别把"能加载"当"能用"

证据分四级，任何"已完成"必须标级：

| 级 | 含义 | 能支撑的结论 |
|---|---|---|
| E0 | 文件存在、JSON 可解析、id 命中 | 只说明"写下来了" |
| E1 | 包启用、注册表加载无报错 | 只说明"没被拒收" |
| E2 | 单体实测（外观/动作/战斗） | 这 1 只在 1 人 1 怪下成立 |
| E3 | 场景实测（同屏/多人/多波） | 极端场景不塌 |

**放行任何门，被放行项 ≥ E2；场景项必须 E3。** "文件在、加载 0 错、命令返回 true" 一律不算功能验收；游戏行为必须我回传才算数。

> 不满形态：拿 E0 静态扫描的结论写"已适配"；用"日志没报错"证明动作接管成功。

### ⑤ 每个数字都要带口径

说"96 个实体"要说明是 `entity.spore.*` 注册键；说"51 只会打人"要说明是 `Monster` 基类口径；估算值必须显式标"估算"，不许混进实测里。同一指标出现多个口径时，全部列出而不是挑一个好看的。

> 不满形态：把"约 81 只可作战"这种估出来的数字，和 class 文件解析出的实测数字并列使用。

### ⑥ 手术式变更

只碰必须碰的部分；不顺手改进无关配置、注释、格式；不重构没坏的东西；自己产生的孤儿（失效条目、临时脚本、TRACE 行）要清掉，与需求无关的历史遗留一律不动。每一处改动都要能直接追溯到我的某一条需求。

### ⑦ 困惑就停

不清楚就停下问，不许带着疑问强行开工，也不许用"我理解你的意思应该是……"糊过去。宁可多问一句，不要错做一天。

### ⑧ 主动反驳，不要顺从

有更简单、更稳、更省的做法就直接说，哪怕和我的要求相反。我明确说过"必要时反驳"。顺着我的话往下做，是我最不需要的。

> 我会认真听的反驳形态："这条不用做，因为 X 已经证明 Y；做了只会增加 Z 风险。"

### ⑨ 不确定就标"待核/未验证"

不要用模糊措辞掩盖不确定（"应该可以""大致没问题"）。写"待实测""待裁决""口径未定"，比写得像结论更有价值。

### ⑩ 结论先行，过程可折叠

先给判断和数字，再给依据。不要用大段推导自证；也不要把同一件事在三个小节里重复三遍。表格 > 段落，能给判据就不要给形容词。

### ⑪ 不重复问已裁决的事

已裁决项（HANDOVER §四 + 《魔改设计决议》变更记录）视为定论。要我改已定设计，必须显式写成"需重新裁决"，并说明改的代价。不要每隔几轮又问一次"要不要考虑换个方案"。

### ⑫ 交付要落文件、给路径、带验证

产出物写清绝对路径、文件用途、**怎么验证它有效**。多阶段任务按固定骨架写：

> **目标 → 准备 → 步骤 → 产出物 → 验证**

这是我在 EF 工作流里指定过的格式，适用于一切复杂任务。另外：**不要排具体日期**，只排依赖顺序与优先级。

## 4 EF 技术结论（实证层，可直接引用）

以下全部基于 `spore_1.20.1_2.2.0j.jar` 与本地 EF 20.14.17 的 class/资源实证，**不是推测**。逐条都值得记住，因为错一条就会白干一天。

### 4.1 数据入口

1. EF 只读 `data/<ns>/capabilities/weapons|armors/*.json` 与 `data/<ns>/epicfight_mobpatch/<entity>.json`。
   `weapon_attributes/` 是 **Better Combat** 格式，不是 EF —— 写在那里等于没写。
2. `config/openloader/data/{imfdata,mowzie_ef_compat,svs}` 内 mobpatch 数 = **0**，自建适配从零开始。
   现存 102 份全在别人 jar 里（SLU 74 / EFMCompat 21 / w.o.w 6 / guardvillagers 1），只能抄结构不能改。

### 4.2 渲染器三态（最容易踩死的坑）

`RenderEngine.registerCustomEntityRenderer` 的 `renderer` 字符串只有三种语义：

| 值 | 行为 |
|---|---|
| `"player"` | 用玩家渲染器 |
| `"epicfight:custom"` | tag 含 `humanoid` → `PCustomHumanoidEntityRenderer`；否则 `PCustomEntityRenderer`。**自定义模型的唯一正确入口** |
| 其他任意字符串 | 当作**原版实体 id**，借该实体的 patched renderer |

第三种的泛型上界绑死 `HumanoidModel`。真菌怪绝大多数是 `EntityModel`，走第三种会 **CCE / 渲染异常（崩溃或不出模型）**，而不是"动作接管"。

→ **真菌人形档唯一正确写法**：`renderer: "epicfight:custom"` + `model: "epicfight:entity/biped"` + `armature` 同值。

### 4.3 `humanoid` 字段的真相

- 它**不在 mobpatch 服务端 schema 里**，只有客户端 `RenderEngine` 读；写错会被静默忽略，日志抓不到。
- 带 `humanoid: true` → `PCustomHumanoidEntityRenderer`（泛型绑 `HumanoidModel`，有 CCE 风险）
- 不带 → `PCustomEntityRenderer`（类型安全）
- 两者在实验里若无差别，结论应是"**全走类型安全分支**"，而不是"带 humanoid 更安全"。

### 4.4 贴图必花

`biped.json` 无 texture 字段，`PCustomHumanoidEntityRenderer` 未覆写 `getTextureLocation` → UV 只能取 spore 原贴图 → **必花屏**。
成本：重绘 biped UV 贴图 **0.5–1 人日/族**，按族合并约 8–10 张。这是"人形档全部转 EF"的唯一真实成本，也是当前唯一待我拍板的事。

### 4.5 同 id 双补丁 = 静默失效

`CUSTOM_CAPABILITIES.put(...)` 是 **plain put，没有 putIfAbsent**；`indestructible` 对 epicfight 声明了 `ordering="BEFORE"` → 它先 apply、EF 后 apply → **普通 `epicfight_mobpatch` 赢**。

→ 若给 Boss 用的 id 再补一份普通 mobpatch，Boss 的 `advanced_mobpatch` 编排会静默失效：文件都在、日志不报错、看起来配好了。
→ 所以 **Boss 必须独占一个不在围城池里的 id**（定：`spore:inf_vindicator`；`spore:hvindicator` 已在精英池，排除）。这是强制项，不是偏好。

### 4.6 兼容性

`indestructible-20.13.0` × EF 20.14.17 已闭合：`mods.toml` 声明 `versionRange="[20.12.4,)"`（20.13.0 是它自己的版本号，不是兼容上界），79 个 EF 类缺失 0，8 个关键方法签名一致。
→ 原先的硬阻塞降级为**5 分钟 scale 抽查**。

### 4.7 非人形怪没有捷径

`spore` jar 内 `animmodels` 条目 = **0**；模型全在 `com/Harbinger/Spore/Client/Models/` 的 Java `EntityModel` 类里。EF 渲染吃 `assets/<ns>/animmodels/entity/*.json`。
→ 非人形怪想让 EF 驱动，**必须自产网格**，没有第三条路。资源包可承载（`JsonAssetLoader` 按命名空间扫，放 `config/openloader/resources/`，不必打 jar）。

### 4.8 模型父类实测（244 个顶层 class 解析）

`EntityModel` 218 / `HierarchicalModel` 12 / `BlockEntityModel` 9 / `HumanoidModel` **3**（未解析 2）。
三个 `HumanoidModel` 泛型全绑 `InfectedPlayer`，即**只有 1 个实体 `inf_player`** —— 而它不进围城、不自然刷怪，实战价值≈0。

→ **判人形不能用"模型父类"**，必须用**关节结构 + 持械能力**。这个判据错误曾导致整张表被误判（见 §6）。

### 4.9 `ArmedModel` 是接口不是基类

唯一方法 `translateToHand`，8 个实现者。但 EF 换网格后它是否仍决定武器挂点**待实测**，故"可持械"一律标 `yes/no/pending` 三值，不要写成结论。

### 4.10 attributes 白名单（写了不报错，但静默忽略）

可用：`impact` / `armor_negation` / `max_strikes` / `stun_armor` / `attack_damage` / `scale` / `chasing_speed`。
高级侧另有：`max_stun_shield` / `has_stun_reduction` / `stun_shield_regan_delay` / `stun_shield_regan_multiply` / `guard_radius` / `stun_immunity_time`。
**不存在**：`attack_speed`、`knockback_resistance` —— 写了等于没写，且日志无提示。

### 4.11 性能测试必须用固定夹具

`siege.js` 用 `Math.random()` 抽池 → 波间不可比。性能数字只能用**手动 summon 固定 20 只 × 3 次取中位**；随机波只用于观感、到达率、失守判定。

### 4.12 日志巡检三条正则（常量池原文，注意上游把 `mob patch` 拼成 `mot patch`）

```regex
Mob Patch Exception: No Entity named (spore:[a-z0-9_]+)
No animation named ([\w:./\-]+)
(Error while deserializing datapack for|Can't deserialize mob capability:?) (spore:[a-z0-9_]+)
```

`/reload` 后搜这三条，能抓出"文件在但没生效"的形态。

## 5 真菌 96 实体分档口径

**口径必须先说清**（这三个数字经常被混用）：

| 口径 | 数值 | 含义 |
|---|---|---|
| 注册实体 | **96** | `entity.spore.*` 键，双源命中无遗漏 |
| 生物承载 | **84** | 96 − 7 投射物 − 3 部件 − 1 纯实体 − 1 未定位 |
| 有攻击 AI | **51** | `Monster` 基类，真正会主动打人 |

分档（2026-10-26 修订版）：

| 档 | 数 | 内容 |
|---|---|---|
| **A** 原生人形 | 1 | `inf_player`（不进围城、不自然刷怪，实战价值≈0） |
| **B** 转 biped | 14 | 11 只 `inf_*` + `hvindicator` + `knight` + `brute`；其中 `nuclea`（半人马）标"视觉待定" |
| **B~** 待裁 | 1 | `inquisitor`（半人形：头/腿 + **单臂** + `Claw1-4`，换 biped 会多出一条不存在的臂） |
| **C** 不动 | 80 | `ogre`（唯一纯非人形精英）+ 非人形自绘 + 投射物/部件/非生物 |

B 档内部还要再分：**可持械 5 只**（`inf_pillager` / `inf_wanderer` / `inf_witch` / `inf_evoker` / `inf_vindicator`）、**不可持械 6 只**（`inf_human` / `inf_villager` / `inf_husk` / `inf_drowned` / `inf_hazmat` / `inf_diseased_villager`）。能给武器动作的只有前 5 只。

按 8:2 混编抽 20 只波次，约 **9–9.6 只走 EF（44–48%）**——"约一半怪有 EF 动作"这个说法是准确的。
