## 一、已发现并已修（属于我改动范围内的问题）

### 1.1 我刚交接的扫描器有 3 处漏报 + 1 处假阳性（严重程度：高）

写对抗夹具（`/tmp/scan_test_fixture.js`，覆盖多行条件头、块注释、模板串、正则字面量、`do-while`、解构、`for-of`、内层函数体等 20 处应报 + 7 处不应报）一跑，**20 处只报出 10 处**。逐条定位：

| 缺陷 | 后果 |
|---|---|
| 只剥离 `//` 注释，**不处理 `/* */`** | 块注释里的花括号打乱块栈 → **其后所有行漏报** |
| 控制流判定只看 `{` 所在**最后一行** | 多行条件头 `if (a &&\n b) {` 被当成函数块 → 漏报 |
| 声明正则要求 `const` 后跟标识符 | `const {a} = x` / `const [a] = x` 解构 **完全漏报** |

修完这三处后，do-while 的尾巴 `} while (...)` 又引发两个新问题，也一并修掉：**假阳性**（箭头函数体被误判成控制块）与**假阴性**（我第一版把真正的 `while` 循环当成 do-while 尾巴吃掉）。最终判据：只有 `do {` 开的块才有尾巴（块栈记种类 `fn`/`ctrl`/`do`）。

**收口证据**：夹具现在恰好报 **17 处、零假阳性**；对修复前的 `svs_damage.js` / `villager_trades.js` 回归分别报 15 / 11（与实测崩点行号一致）；对修复后的副本/test4/仓库三个目录均报"干净"。

### 1.2 由此纠正一个数字错误：修复前真值是 49 处，不是我写的 48（严重程度：中）

旧版扫描器漏掉多行条件头，于是漏报了 `svs_damage.js` 里 `else if (...) {` 块内的 `const mult = DMG_MULT[...]` —— 那是**共生 ×1.5 增伤路径上的真雷**（已结合玩家打 spore 怪时第二次触发必抛）。该处在我重写整个监听器时已一并提升，所以修复结果不受影响，但**文档与 commit message 里的 48 是错的**，HANDOVER 四点八已改为 49 并注明成因（commit message 不重写，避免与并发会话冲突）。

### 1.3 POTB 探针第一版走 `System.out`，不进 `latest.log`（严重程度：中）

本包 AsyncLogger 配置 `wrapSysOutSysErr=false` → `System.out.println` 只落 `logs/console.log`，而所有排查指令（含 HANDOVER 自己的）都让人看 `latest.log`。**一个"看不见的探针"正是这个项目反复踩的坑**，故改为 SLF4J 并重新构建/部署/实测（1.0.2）。现在 `grep svs_tweak logs/latest.log` 能拿到全部 4 行（配置注册告警 + 取消器 ×2 + 探针 ×2）。

## 五、第一性原理复核（治本 or 治标）

1. **const 地雷**：根因是 Rhino 对「块内声明」的作用域实现（第三方 jar，不可修）→ 治本手段是**让我们的代码不再依赖该行为**（结构上消除）+ **让复发可被机器拦住**（扫描器 + 提交前校验）；残留风险仅剩"扫描器自身有洞"，已用对抗夹具压到零误报/零漏报。
2. **`event.trades` CCE**：根因是 KubeJS 对 `Map` 实例的属性访问拦截（`NativeJavaMap.containsKey(String)`），且该异常**无法用 JS try/catch 兜住** → 治本手段是**不再触碰该对象**（换 architectury 静态 API），而不是给同一行加 try/catch（那只会掩盖）。已把"哪些原版/包装类型可安全触碰"的结论写进 HANDOVER 与 svs_tweak README，避免下次再试探。
3. **POTB NPE**：根因不是 NPE 本身，而是**构建缺陷让 5 个 mixin 从未注册**（MANIFEST 缺 `MixinConfigs`）→ 治本手段是修构建并**给它加自检探针**（否则下一次"静默失效"同样没人发现）；`require=0` 保留为版本漂移防线，探针负责可观测。
