## F4 围城 HUD NaN —— 规格书给的三个候选**很可能都不行**，请先跑探针

实证（`mm.jsmappings`，Rhino 的 SRG→JS 名映射表）：`dayTime` / `getDayTime` / `getGameTime` **都挂在 `Level` 类条目下**（同一批还有 `getLevelData`/`getChunkSource`/`getRandom`）；而本环境**成员解析按类建键**，`server.overworld()` 的运行时类是 `ServerLevel`。

同时：`maxHealth` 这类**由 getter 支撑的属性**在 modded 实体上是**能用**的（9-25 限伤现场 `maxHp` 取到 265 ✓），而 `dayTime` 是**公共字段**、且用户实测出 NaN ✗ —— 两种取用路径的表现不一致，**机制尚未完全钉死**，所以别盲改。

**先跑一次探针定名**（GLM 执行，tepm 放 `kubejs/server_scripts/_probe.js`，跑完删）：

```js
// 一次性探针：把候选读法逐个打印，一次启动定名（严禁留在包里）
let P_TICK = 0
ServerEvents.tick(event => {
  if (!event.server) return
  P_TICK++
  if (P_TICK !== 200) return          // 世界加载后 10 秒触发一次
  const srv = event.server
  const lv = srv.overworld()
  console.info('[PROBE] server=' + (typeof srv) + ' level=' + (typeof lv))
  let a = 'ERR', b = 'ERR', c = 'ERR', d = 'ERR'
  try { a = lv.dayTime } catch (e) { a = 'ERR:' + e }
  try { b = lv.getDayTime() } catch (e) { b = 'ERR:' + e }
  try { c = lv.getGameTime() } catch (e) { c = 'ERR:' + e }
  try { d = srv.getTickCount() } catch (e) { d = 'ERR:' + e }
  console.info('[PROBE] dayTime=' + a + ' | getDayTime()=' + b + ' | getGameTime()=' + c + ' | server.getTickCount()=' + d)
})
```
读数含义：能用的那个直接替换 `siege.js` 的 `worldDay` 计算；若 **四个全是 ERR**，则 HUD 的世界天数改从**服务端自己的日记数**（`siege.js` 已有 `siegeTick` 秒计数，配合 level persistentData 落盘）来，或让 `svs_tweak`（F6/F7 本来就要重建）加一个 `SvsTime.dayOf(ServerLevel)` 小工具。
