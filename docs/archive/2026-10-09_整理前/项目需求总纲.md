# Symbiote vs Spore 整合包 · 项目需求总纲

> 整理自项目开始以来的全部要求，仅做归纳简化，不改变原意。日期：2026-09-22。

## 一、项目目标

做一个以**史诗战斗（Epic Fight）为战斗核心**、以**打 Boss + 探索黑魂结构 + 抵抗真菌（Spore）为主线**的整合包，仓库为 GitHub 私有库 `233zsq/symbiote-vs-spore`，MC 1.20.1 / Forge，最终产出可导入 PCL 的整合包。

## 二、参考学习对象（持续对标）

| 整合包 | 学什么 |
|---|---|
| Immersive Fight 4.2.9（沉浸战斗） | EF 模组设置/优化/魔改、EF 适配数据包（imfdata）、汉化与资源包做法 |
| DUEL OF THE END（终焉决斗） | EF 附属选型、数值框架（InControl×GameStage×场地三轴）、FTB 任务写法、Boss 战设计 |
| Construct Technological Innovation（CTI） | 匠魂附属选型、数据包驱动匠魂材料、FTB 任务（暮色章节借鉴） |
| 龙之冒险：新征程 | FTB 任务多板块结构、MCBBS 格式整合包打包方式 |

## 三、模组管理要求

1. 用户提出想加的 mod（给名称/链接/或放入 `E:\mcmp_test\dl\` 各批次文件夹），**由我先审查兼容性**（版本/依赖/冲突/字节码实证），能下就下，下不了用户自己下
2. 用户在 PCL 上自行增减模组后会导出整合包发来——**收到先 diff 对账再合并**
3. 优化模组、汉化、魔改可以直接抄沉浸战斗等参照包
4. 每次变更后给**总模组清单**；模组增删改查完成后再做主线和数值魔改

## 四、崩溃与问题处理原则

- **先修不删**：崩溃/冲突优先修复（含改 jar 内 mixin 配置等手段），修不了的保留并向用户报告
- 每次修复要有实证（日志/截图），改动落仓库 → 同步副本/实例 → 实证 → commit 证据链

## 五、FTB 任务线设计

1. 模仿龙之冒险和 CTI，**分多个板块/章节**，覆盖所有重要模组，把 Boss、武器、匠魂讲清楚
2. **复现解锁任务**：阶段化解锁，主线线性连贯；武器图鉴等介绍说明类不锁阶段
3. 主线 = **打 Boss + 探索黑魂结构 + 抵抗真菌**，可细分章节
4. 章节顺序约定：**下界不做第一章（直接取消）**；天灾防线改为暮色森林后开放；暮色森林章节借鉴 CTI；**黑魂章节放在暮色之后**
5. **每个阶段的 Boss 打完后直接奖励当前强度的匠魂材料**

## 六、数值体系

1. 采集全包**武器数值**（按攻击×攻速的 DPS 排列）和 **Boss 数值**（按血量排列），先简单等级排序给用户过目，再做下一步细分和魔改
2. 输出四张 Excel 表（武器/敌对生物/Boss/中立生物）放桌面：按 mod 分类、mod 间按内容量降序、组内按 DPS 或血量/攻击/护甲降序；各 mod 分组上色（不用红色），**EF 适配的武器和生物用红色特别标注**
3. EF 适配状态要体现在表格里，作为魔改依据

## 七、EF 适配工作

1. 学习 DOTE/IF 的 EF 适配体系与附属选型，先查 CurseForge 有无现成适配 mod，没有就自己写数据包适配（不改 jar）
2. **批量模板化兜底**：按攻击/攻速给未适配武器批量生成 EF capability JSON
3. **精做后置**：单独自定义适配暂不做，用户试玩后点名手感不对或想精做的武器再单独处理
4. 生物 mobpatch 只对人形怪做（大型/非人形生物不做动作适配，用数值/机制平衡）
5. 面向用户的持续目标：看哪些 mod 适配好史诗战斗，要不要加 EF 适配 mod 或自己做适配

## 八、汉化要求

1. 分类整理模组清单：每个 mod 有基本介绍，**重要 mod 至少 50 字介绍**
2. 列出需汉化的 mod 并**标注硬编码的 mod**；先做力所能及的汉化，困难的（硬编码等）另列清单
3. **魂类游戏/同人 mod 汉化必须查相关内容**，贴合已有通行译名——例：悟空装备用《西游记》原名（凤翅紫金冠、如意金箍棒等）

## 九、合规要求

查看各 mod 开源协议（CurseForge），审查整合包的**魔改、汉化、mod 使用**是否符合各 mod 协议，出审查报告。

## 十、工作方式约定

1. 可使用 Qoder CN CLI 辅助；**qoder 模型用智谱 GLM-5.3-Flash，不用 DeepSeek**
2. 需要控制电脑测试时可询问用户，由用户测试检查；也可用启动脚本直接启动实测
3. 不做无意义的重复测试（如大量键位测试），**快点出成品**
4. 每次收到新批次 mod：审查 → 安装 → 启动测试 → 修复 → pw 登记 → commit

## 十一、魔改设计决议（2026-09-23 讨论定稿）

流程与机制的详细决议见 `docs/魔改设计决议.md`，要点：真菌围城（7 日周期/暂停回村 5 分钟预警/不强加载）、火种绑定（挂文礼文明等级）、真菌币经济、难度三档进游戏内、单次受伤上限+限伤减伤爬升模板、多人惩罚三原则、结构密度提纯+关键结构定点、武器解锁连战（Gateways 终局支线）、铁魔法弱化、匠魂定位保底逃课、共生体×EF 分期适配、Boss mod 分流（主线灾变血源 SLU/野外探索线/竞技场日课线）。

开发分工：**K3 控方向与验证，qoder GLM-5.3-Flash 写码**；mixin/字节码/多人同步/防作弊代码 K3 亲自写或逐行审。
