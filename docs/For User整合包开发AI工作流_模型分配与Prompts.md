## 1. 模型资产盘点

### 1.1 五模型定位

| 模型 | 载体 | aa 指数 | 相对单价 | 本工程中的角色 |
|---|---|---|---|---|
| Kimi K3 | Kimi Code | 44 | 订阅制（剩 50%，**9.25 过期**） | 仓库级 agentic 攻坚：一次看懂整个 packwiz 仓库的活 |
| glm5.3 | Qoder | 45 | ×0.6 | 最强编码 → **攻坚预备队**，非默认选项 |
| glm5.3flash | Qoder | 42 | ×0.05 | **主力工作马**，性价比断层第一 |
| qwen3.8max | Qoder | 40 | ×0.4 / 闲时 ×0.2 | 闲时中档 + **跨家族复核员** |
| qwen3.8flash | Qoder | 未知（勿按 42 估） | ×0.08 / 闲时 ×0.04 | **闲时批量机**，aa 未知 → 产物必校验 |

### 1.2 成本结构分析

以 glm5.3flash 的单次任务成本为 1 单位：

| 模型 | 普通时段 | 闲时时段 |
|---|---|---|
| qwen3.8flash | 1.6 | **0.8（全场最低）** |
| glm5.3flash | **1.0（普通时段最低）** | 1.0 |
| qwen3.8max | 8 | 4 |
| glm5.3 | 12 | 12 |
| Kimi K3 | 订阅额度（沉没成本，9.25 清零） | 同左 |

两个关键推论：

1. **能力差距与价格差距严重不对等**。aa 42 → 45 只差 3 分，价格却是 12 倍。对绝大多数"有标准答案、可验证"的整合包工程任务（写脚本、填配置、生成 JSON），glm5.3 相对 flash 的边际提升远不值 12 倍——它只该用于 flash 两轮打不下的硬骨头。
2. **qwen3.8flash 只在闲时比 glm5.3flash 便宜**（0.8 < 1.0）；普通时段它反而贵 60%（1.6 > 1.0），且 aa 未知。**普通时段禁用 qwen3.8flash，批量任务攒到闲时跑。**

### 1.3 Kimi K3 的 15 天窗口策略（9.10 → 9.25）

K3 额度过期清零，等于已预付的"免费算力"。窗口内凡是**需要长上下文、跨文件、自主多步执行**的活优先给它（Kimi Code 是 CLI agent 形态，天然适合仓库级任务；Qoder 是 IDE 形态，适合交互式单点编辑，别反过来用）。

| 时间 | 对齐路线图 | K3 承担的活 |
|---|---|---|
| 9.10–9.12 | ① 底座搭建 | packwiz 仓库脚手架、Git 纪律文件、校验脚本（P1） |
| 9.12–9.14 | ② 核心战斗验证 | EF 手感基准测试清单、配置项速查表生成 |
| 9.14–9.20 | ③ 次核心攻坚 | 次核心三连的崩溃/异常日志归因（P2）、键位下发方案 |
| 9.20–9.25 | ⑤ 魔改框架先行 | KubeJS 骨架 + 武器线谱系框架 + 五阶段门控 DAG + 任务线章节结构——**框架在窗口内定型，批量填充留给 Qoder** |

9.25 后 K3 退场，S 级任务全部路由到 glm5.3。

## 2. 任务分级与路由规则

### 2.1 四级任务分类

| 级别 | 定义 | 本包实例 | 路由 |
|---|---|---|---|
| **S 级（攻坚）** | 无标准答案、错了代价大、需要跨系统推理 | EF 版本耦合冲突；Symbiote 劫持×EF 输入拦截设计；sporeconfig 红线参数；spark 火焰图归因；门控 DAG 设计；武器线谱系设计/调整（P13） | glm5.3（窗口内可 K3） |
| **A 级（工程代码）** | 有标准答案、需 API 正确、可 /reload 验证 | 单文件 KubeJS/CrT 脚本、CompatLink 批次映射、Default Options 键位下发、数值对齐设计 | glm5.3flash |
| **B 级（批量结构化）** | 模板固定、量大、可机器校验 | EF capability JSON 批量、战利品表、配方 JSON、In Control! 规则、任务条目、许可证清单初稿 | 闲时 qwen3.8flash |
| **C 级（杂务）** | 低风险文字 | commit message、README、更新日志、发布页文案草稿 | glm5.3flash 随手做 |

### 2.2 路由六条规则

- **R1 先便宜后贵**：任何任务先派该级别最便宜模型；**同一任务连续两轮不达标 → 升一级**，并把失败输出一并喂给强模型（让它改错题，比从零写更省 token）。
- **R2 订阅优先**：9.25 前，凡"需要一次看懂整个仓库"的活优先 K3；零散小批量生成不给 K3（浪费额度且不吃闲时折扣）。
- **R3 跨家族复核**：A/S 级产物由**不同家族**模型复核（GLM 出稿 → qwen3.8max 审，或反之）。同家族互审容易共享盲区。
- **R4 批量必校验**：B 级产物先过 JSON schema/语法校验，再由 glm5.3flash 抽检 10%，全绿才入库。qwen3.8flash 的 aa 未知，这条是它的上岗前提。
- **R5 闲时攒批**：B 级任务平时攒在待办清单里，闲时（以 Qoder 公示时段为准）一次性跑批。
- **R6 红线不降级**：以下四类**禁止 qwen3.8flash 单独承担**——EF 版本耦合决策、Spore 腐蚀相关参数（不可逆）、原版干预政策【待定】项的决策与武器线谱系设计、发布合规核对（许可证/授权）。

### 2.3 校准实验（第一周做一次）

aa 指数近期争议大、规则改过两轮，只当参考。用自己的数据校准路由器：挑三道本包真实任务（一道 A 级如 P3、两道 B 级如 P5），分别喂 glm5.3flash / qwen3.8max / qwen3.8flash，记录**一次通过率**。哪家的实测通过率和 aa 排序不符，就按实测改路由。qwen3.8flash 尤其要先测再放大批量规模。

## 3. 分阶段执行工作流（对齐方案第 6 章）

### 阶段① 底座搭建（9.10–9.12）

- **K3**（P1）：packwiz 仓库初始化、`pack.toml`、`.gitignore`（排除 `mods/*.jar`）、目录结构、提交规范、JSON 校验脚本。
- **glm5.3flash**：README、实例配置说明。
- 验收：空包稳定启动、`pack.toml` 入库、首次 commit 完成。
- ⚠️ 世界生成（Terralith）决策在阶段④之前冻结，本阶段只在开发实例验证。

### 阶段② 核心战斗验证（9.12–9.14）

- **K3**：生成 EF 手感基准测试清单（连段/翻滚无敌帧/格挡/体力逐条）与 EF 配置项速查文档。
- **人工实测**（AI 不能替你按翻滚）：逐项记录手感数据。
- **glm5.3flash**：把实测记录整理成《战斗手感基准文档》，锁定 EF 20.14.x 版本号。
- 验收：基准文档 + EF 版本锁定 commit。

### 阶段③ 次核心攻坚（9.14–9.20）

三个次核心各占一批、单独验证（方案 4.2）：

- **Symbiote × EF**：人工实测三项（键位/劫持/渲染）；**K3** 做异常日志归因（P2）；**glm5.3** 设计键位下发与劫持调频方案（S 级）；**glm5.3flash** 写 Default Options 文件。实测不过线 → 启动降级预案（P12）。
- **Spore**：**glm5.3** 出 sporeconfig 三档框架（红线，P8）；**glm5.3flash** 按框架填配置与 In Control! 规则初稿；**qwen3.8max**（闲时）复核（P11）。
- **Sword Soaring / Nightfall**：数值对齐走 B 级批量（P5），闲时 qwen3.8flash 生成 + glm5.3flash 抽检。
- 验收：次核心三连实测记录全部过线（或降级决策已执行）。

### 阶段④ 内容填充（9.18–9.24，可与③并行）

- 分批加模组与进档实测为人工执行；**崩溃归因在窗口内派 K3，窗口外派 glm5.3**（P2）。
- **Saint's Dragons**：群系标签注入数据包 → B 级批量（P5 变体）；Mount Fix 回归测试人工。
- **RoadWeaver**：结构连接配置 → glm5.3flash；版权争议评估（方案 3.7 ⚠️）为人工拍板，AI 只整理材料。
- 验收：全量清单冻结，各批无崩溃。

### 阶段⑤ 魔改攻坚（9.20 起，周期最长）

- **框架层**（窗口内 K3，过期后 glm5.3）：KubeJS 骨架、武器线谱系落地框架（9 条武器线的节点配置与数值表，方案 3.3）、五阶段门控 DAG、任务线章节结构（P1 变体）；武器线设计本身走 P13（S 级）。
- **脚本层**（glm5.3flash，P3/P6）：模组配方收束与武器线节点落地、自定义物品、Xaero's/指南针/传送改造脚本。
- **批量层**（闲时 qwen3.8flash，P4/P5/P7）：EF 能力 JSON、战利品表、任务条目；glm5.3flash 抽检。
- **复核层**（闲时 qwen3.8max，P11）：跨家族审查 A 级产物。
- 验收：每批产物 `/reload` 通过 + 进游戏实测清单过线 + commit 标注模型批次。

### 阶段⑥ 测试调优

- **spark 报告分析**：S 级，窗口内 K3 / 窗口外 glm5.3（P9）。
- 压测执行与全新存档验收：人工。
- 验收：压测报告 + 实测内存门槛写入发布页。

### 阶段⑦ 发布合规

- **qwen3.8max**（闲时，P10）：许可证核对表**初稿**。
- **人工逐项核对**（红线）：AI 给出的授权状态一律到 CF/Modrinth 原页核实，不作合规依据；FTB 系仅限 CF、opt-out 模组引导手装、RoadWeaver 争议单独评估。
- **glm5.3flash**：发布页描述、MC百科投稿文案草稿。
- `packwiz curseforge export` / `modrinth export` 人工执行。

## 5. 工程纪律与红线

1. **ID/键名/模组行为是幻觉重灾区**：一切物品 ID 以 `/kubejs hand`、`/ct hand`、F3+H 现场为准；AI 产物中的 ID 一律视为占位符，未核实不进版本库。
2. **EF 系列锁定 20.14.x**：任何模型提出"升级 Epic Fight 或其附属"一律拒绝；确需升级时由人工决策，并触发全量武器动作回归测试。
3. **AI 不替你实测**：手感、命中判定、骑乘崩溃、劫持交互、道路生成质量必须进游戏验证；每个脚本类 prompt 已内置"验收清单"要求，验收不过不 commit。
4. **commit 标注模型批次**：如 `feat(loot): Calamity 掉落链 [qwen3.8flash+P11过审]`——翻车时按批次精确回滚，也能积累各模型的实测通过率数据（喂给 2.3 校准）。
5. **世界生成定型前不动正式存档**：Terralith 及一切 worldgen 覆盖先入开发实例验证。
6. **合规人工拍板**：许可证、RoadWeaver 版权争议、FTB 系分发限制——AI 只打草稿，最终结论必须人工到原始页面核实。
7. **原版内容政策【待定】**：决策落地前，任何模型不得改动原版配方/数值/门控；AI 若主动提出原版修改建议，归入"阶段⑤平衡实测后决策"待办，不当场执行。
