# 新加入的模组9：审查与合入建议

审查日期：2026-10-26。范围是用户指定的七个本地JAR、官方页面、现有test/母本与两个参考包。**本轮只审查和更新资料，没有安装、改配置、改任务或启动游戏；剧情工作暂停。** 下文“建议”均未成为玩法裁决。

## 1. 结论与优先顺序

| 候选及实际版本 | 建议 | 入包前必须解决的事项 |
|---|---|---|
| Quest Enhance 3.13 | 第一批隔离验证，最贴近当前任务美术问题 | 不能按纯客户端插件处理；客户端与服务端保持同版，验证任务同步、保存与旧任务桥 |
| Hadean Breathe 0.25.7 | 第二批Boss内容候选 | 补VzlingLib；限制新增结构/矿物生成；验证原生限伤、武器动作和伤害归因 |
| Book of Dragons 1.31 | 第二批龙养成候选，与圣龙先划清职责 | 补AzureLib；决定龙巢取得方式；测试Leawind、EF和骑乘相机 |
| Celestisynth 1.3.4 | 保留候选，当前适配链未闭合 | 沉浸战斗的CELEpic 1.0不能直接用于此版本，详见专项报告 |
| Celestisynth Fix 0.1 | 随Celestisynth 1.3.4成套验证 | 只修客户端动画缓存泄漏，不提供EF兼容；不单独安装 |
| Super-Tier Magic 3.6.3 | 暂缓默认合入，先做规则约束方案 | 百分比强制扣血、时停、飞行、地形破坏及经验等级减免成本，会改变现有战斗体系 |
| Spawn 4.0.8 | 留作世界生态改版候选 | 直接介入群系生成，现有worldgen冻结条件下不宜整包默认加入 |

推荐顺序体现验证成本和与当前需求的关系，不代表已批准以上安装。先单批验证，再组合；不要把七个JAR一次丢入现有世界后排错。

## 2. 当前基线与证据范围

- Minecraft 1.20.1 / Forge 47.4.23；EF固定20.14.17。游戏JDK21，构建工具JDK17。
- 本轮实盘：母本226个、test229个顶层JAR；参考IF308个、Otherworld400个。这七个候选均未安装；Legendary Bosses先前准备文件仍不等于已安装。
- 当前已具备GeckoLib 4.8.4、PlayerAnimator 1.0.2-rc1+1.20、FTB Quests 2001.4.22、Iron's Spells 3.16.3；**缺AzureLib、VzlingLib**。
- 七个JAR的ZIP CRC检查通过，class主版本均为61，即Java17。这里只说明归档完整和字节码基线，不是安全认证或加载通过。
- 全部文件名、依赖声明、SHA-256、语言键和资源路径见[原始盘点](data/模组9审查_2026-10-26.json)，便于筛选的清单见[审查CSV](data/模组9候选清单_2026-10-26.csv)。代码核对与参考包规则见[专项证据](data/模组9专项研究_2026-10-26.json)。

资源数量按`data/<命名空间>/<实际目录>/`精确计数，**tags、进度中的解锁配方、assets中同名目录不算注册定义**。资源存在、Java注册、运行时可获得、功能通过是四种证据层级。

## 3. 逐项审查

### Quest Enhance：值得优先验证，但并非只换皮肤

实际文件`quest_enhance-1.20.1-forge-3.13.jar`，modId `quest_enhance`。要求FTB Quests至少2001.4.22，当前恰好满足最低声明。英文、简中各195键。

它能提供实体展示、击杀任务用实体模型替代刷怪蛋、任务与内容页背景、描述媒体和编辑增强，适合解决Boss展示和基础任务界面的问题。它不会自动修好错误物品ID、错误头像、剧情和奖励，也不能代替任务设计。

关键实现：`QuestMixin`同时扩展`writeData/readData`和`writeNetData/readNetData`；`ChapterMixin`也扩展序列化；`TaskCompletionMixin`参与完成通知，`QuestTaskRequirement`新增`quest_enhance_minimum_tasks`，会改变一项任务需要完成多少子目标。官网的客户端用途描述不能覆盖这些实现事实。

建议先只试本地资源背景和描述中的Boss模型。保留用户要求的16×16正面头像、装备材料实物图标；实体模型用于详情页和预览，不自动把全书图标替换成转动模型。最低任务数保持默认，不顺带改变完成条件。试验需覆盖旧SNBT载入、编辑保存后重进、团队进度、奖励只领一次、新旧客户端不匹配时的行为，以及现有实体展示字段是否重叠。双人验证仍按用户此前要求保留待验，不能用单人代签。

### Hadean Breathe：下界战斗内容候选

实际文件`hadean_breathe-0.25.7-1.20.1-forge.jar`，modId `hadean_breathe`；强制依赖`vzling >=0.98.8`，当前缺失。英文和简中各148键，暂不需要全量重译。

实物含3个结构定义：`abandoned_campsite`、`blackstone_temple`、`enforcer_arena`，另有2组下界矿物feature/biome modifier。115份配方定义分别位于`hadean_breathe`和`minecraft`命名空间；不能把命名空间不同直接认定为覆盖原版，实施时按资源ID逐件比较。

Java注册了`hadean_enforcer`、`hadean_smasher`、`hadean_blaster`三类Boss实体，以及守卫、兽类、弹射物。官网较早介绍的“一个Boss”不能当作本JAR的完整清单；反过来，注册三个也不能保证三个都具有完整自然流程和实战品质。

`ModConfig.Common`给执法者默认250生命、10攻击、12护甲、单次伤害上限12、受击减伤时间25tick；这些是候选代码默认值，不是SvS实测。Smasher也有cap/time配置，Blaster类内有固定返回值。应测试EF多段攻击、法术和炮塔遇到原生限伤时的表现，不额外恢复已经否决的全局限伤层。未发现随包提供的EF武器能力或mobpatch资源；保留原生Boss AI与证明EF可正常对战要分开记录。

可以扩展下界探索和军械材料内容，本轮不分配主线章节、不写新剧情。worldgen继续冻结；若以后采用定点竞技场，必须同时提供材料和召唤/重战的可用路径，不能禁完结构与矿后留下断链。

### Book of Dragons：完整龙养成，不是说明书附属

文件`bookofdragons-1.31-1.20.1.jar`，modId `bookofdragons`；需`azurelib >=3.1.3`，GeckoLib不能替代它。实际包以驯龙高手风格的龙种、驯服、骑乘、遗传/变种和龙巢为核心；`roost_config.json`列有Night Fury、Skrill、Gronckle等龙种权重。

有5个龙巢结构/结构集，**没有5个新群系**；对应`tags/worldgen/biome`只是龙巢允许的群系标签。配置可调整各类龙巢的龙种权重，但这不是关闭所有结构生成的总开关。

客户端4个Mixin处理骑乘、相机翻滚/位置、鼠标，priority为1500。可关闭镜头翻滚、调距离、选骑乘视角；仍须与Leawind、EF战斗切换、上下坐骑和重进保存组合验证。两套龙模组可以同时存在于候选方案，但应让圣龙承担原有探索职责，龙之书承担可选养成；不要再附加通用强制驯服去改造它的原生龙。

仅见英文293键，无自带简中。真正合入后再按现有汉化资源包方式补译，不改原JAR；龙名先定术语再写任务。没有启动测试，不能承诺与圣龙、AzureLib和渲染栈完全兼容。

### Celestisynth与Fix：版本组合是当前阻断点

`celestisynth-1.20.1-1.3.4-all.jar`要求GeckoLib至少4.4.2、PlayerAnimator至少1，当前已有。英文224键、简中114键，键数差110代表待对照条目，不自动等于110条必须显示的未译文本。

它提供高特效武器和原生技能；实际有30份配方、4组矿物/地表feature及biome modifier，没有随包EF武器能力资源。其Better Combat兼容代码不能充当EF适配。

另有一个元数据遗留项：可选JER依赖的版本范围仍是字面量`jer_version_range`。当前test/母本没有`jeresources`，因此不把它列为当前缺前置阻断；以后新增JER时需先验证加载器如何解析，不能按正常版本范围放行。

IF使用Celestisynth **1.3.1 + CELEpic 1.0 + EF20.14.17**。CELEpic的26项Celestisynth类引用在IF旧版存在，在候选1.3.4全部缺失；旧`com.aqutheseal.celestisynth`包名已经替换为`org.thecelestialworkshop.celestisynth`。这是明确的静态不兼容，不能用元数据宽版本范围放行。可研究旧版成套复现，或寻找/制作面向1.3.4的新适配；EF保持20.14.17。

`celestisynth_fix-0.1.jar`的唯一功能类在客户端世界卸载/断线时清空`CSAnimator`三张静态Map。1.3.4中对应公开字段存在，静态字段核对通过；不等于联机、切世界和内存增长已经验证。它没有声明强制Celestisynth依赖，不能因此单装。若改走1.3.1路线，**这份Fix所引用的新包名又不匹配旧版**，必须重新选择修复方案，不能把三者机械打包。

### Super-Tier Magic：需要独立平衡方案

文件`super-tier-magic-3.6.3.jar`，实际modId为`flametalisman`；要求Forge至少47.4.0，当前满足。英文/简中各215键。不是Iron's Spells法术附属，铁魔法禁用清单和EFS-ISS耗蓝不会自动约束它。

关键风险都有代码依据：

- `SwordPercentage`经`WardManager.forceLoss`直接改生命，默认比例5%～10%，还受附魔倍率影响；可能绕过普通受伤事件、远程规则与击杀归因，需要实际验证。
- `ArtifactCosts`以原版经验等级缩放消耗，默认100级趋于免费；这与拟议DND角色等级不是同一数值，不能混用。
- 默认打开云飞行；`flightCheat=false`只关闭免道具快捷飞行，不等于关闭道具飞行。实际入口是`survivalCloudFlight`。
- `thunderAbyss`、`thunderStormTerrainDamage`、`boltTerrainDamage`默认开启地形切割/破坏；还有时间、免疫、护盾等独立系统。这里的Abyss名称不能据此认定新增了维度。
- 古代僵尸自然生成、增援及剑之领主另成一套遭遇；需核对围城AI负担、Boss来源与奖励是否重复。

若以后选择加入，建议实验配置先关闭以上地形破坏、独立飞行和自然增援，百分比强制扣血归零，再逐项验证能否通过正常伤害管线接入。仅删配方不能防止战利品、任务或其他途径取得；时停/清空效果需另核对黑名单与Boss阶段。上述均为配置建议，本轮未写入。

官网许可证与本地JAR标记不一致（页面ARR、JAR MIT），因此不据元数据宣称可重分发或修改。安装验证与公开发布许可分别处理。

### Spawn：是生态与世界生成扩展，不是简单刷怪控制

`spawn-4.0.8-1.20.1.jar`约83.6MB，不含额外强制前置。实际有10个新群系、8个结构、58份configured feature、57份placed feature和34个biome modifier。此前按路径子串统计会混入标签，本报告已按实际目录纠正。英文947、繁中372键，无简中。

关键风险不止结构：`OverworldBiomeBuilderMixin`直接改海岸/海域等群系选择，`MultiNoiseBiomeSourceMixin`合并群系列表，另有结构定位和自然生成相关Mixin。已读`SpawnServerConfig`主要控制生物行为和原版小改动，未见能关闭全部群系注入的总开关。**空覆盖结构集或biome modifier不足以证明世界生成已被关闭**，也不应直接修改ARR原JAR去删Mixin。

若目标只是多一些动物，它的引入成本偏高；若未来明确改版海洋/生态，可以独立评估新世界方案。现存世界未探索区块的分界、地形栈、路网定位和性能需要同批验证。当前建议暂存，不借本次审查解除worldgen冻结。

## 4. 后续实施批次与验收

1. 任务显示批：Quest Enhance，仅本地资源，验证序列化/保存/领奖/团队同步；不顺带改任务逻辑。
2. 内容批：Hadean与龙之书分别补齐Forge1.20.1前置、先单独再组合；确定冻结生成条件下的完整获取链。
3. 武器批：先解决Celestisynth版本与EF适配组合，再验证七类能力武器、原生远程武器和耗蓝/伤害归因。Fix随目标版本选择。
4. 规则批：DND方案、Super-Tier与坐骑召唤分别做机制选择，不与前述内容批捆绑。Spawn另列生态改版。

获准实施后再建立独立游戏目录/独立测试世界、保存目标清单与回退、确认客户端退出后安装。用户负责游戏验收，联机待验项保留；单人加载不能代替专用服务端检查。当前无需新增skill，JAR、配置和文档审查已有工具足够，未安装与本轮无关的skill。
