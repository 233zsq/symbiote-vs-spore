## 0. 使用纪律（先读）

- 本文所有 `somemod:*`、`somemod:overpowered_blade` 等均为**占位符或示例**。一切物品 ID / 配置键名以 `/kubejs hand`、`/ct hand`、F3+H 现场核实为准，未核实不进版本库。
- **原版干预政策【待定】**：决策落地前，任何脚本 / 配置不得触碰原版配方、数值与门控。
- **EF 锁定 20.14.x**：任何「升级 Epic Fight 或其附属」的建议一律拒绝。
- 涉及 Symbiote / Fungal Infection: Spore / Saint's Dragons 的行为描述均属**无公开共存先例**，以实测结论为准，相关条目标注【需实测】。

## 1. 生效方式速查表

| 改动类型 | 位置 | 生效方式 |
|---|---|---|
| 模组 config 数值 | `config/`（各模组） | 通常需重启；个别模组支持游戏内修改 |
| 新存档默认值下发 | `config/defaultconfigs/` | 仅对**新建存档**生效（Forge 首次进档时拷贝为该存档配置） |
| KubeJS 物品注册 | `kubejs/startup_scripts/` | **需重启游戏**，`/reload` 无效 |
| KubeJS 服务器脚本 | `kubejs/server_scripts/` | `/reload` 热重载 |
| KubeJS 客户端脚本 | `kubejs/client_scripts/` | 客户端 `/reload` |
| CraftTweaker 脚本 | `scripts/` | `/reload` |
| 数据包 JSON | `kubejs/data/` 或 `config/openloader/data/` | `kubejs/data/` 随 `/reload` 重载；openloader 随存档数据包加载，建议重启确认 |
| FTB Quests 任务 | `config/ftbquests/`（SNBT） | 编辑器保存即生效，重进世界后加载 |

注意（1.20.1 版本事实）：数据包目录为**复数形式**（`recipes/`、`loot_tables/`）；物品数据用 NBT（1.20.5+ 才改组件）。

## 2. 战斗装备平衡线脚本（方案 3.3）

文件：`kubejs/server_scripts/weapon_balance.js`（`/reload` 热重载）

作用：把「模组武器数值参差、材料成本混乱」收束进 3.3 的内容带与武器线谱系——移除数值倒挂的廉价超标配方、按模组收束材料、对齐原版模式下的兜底数值。**平衡只针对模组武器，原版内容默认完全自由。**

```javascript
// server_scripts/weapon_balance.js：战斗装备平衡线（/reload 热重载）
// 原则：原版内容默认完全自由（干预政策【待定】，见 3.3 原版自由带）——不删配方、不锁阶段、不改数值；
//       平衡与材料收束只针对模组武器（模组 ID 与物品 ID 以 /kubejs hand 实测为准）
ServerEvents.recipes(event => {
  // 1) 数值倒挂的模组武器：移除其廉价超标配方，改由任务/战利品按武器线节点投放
  event.remove({ output: 'somemod:overpowered_blade' })

  // 2) 材料收束仅作用于该模组的武器配方：核心部件统一换成本包"精制铁锭"
  //    （kubejs:refined_iron_ingot 见 3.4；按 mod 过滤逐模组处理，不触碰原版配方）
  event.replaceInput({ mod: 'somemod', type: 'crafting_shaped' },
    '#forge:ingots/iron', 'kubejs:refined_iron_ingot')
})

// 模组武器的原版模式兜底数值对齐（EF 模式判定数值见 3.8）
ItemEvents.modification(event => {
  event.modify('somemod:overpowered_blade', item => { item.attackDamage = 6 })
})
```

逐段解释：

1. `event.remove({ output: ... })` —— 移除数值倒挂的廉价超标配方；该武器改由任务 / 战利品按武器线节点投放，删除前必须确认投放路径已就位，否则物品绝版。
2. `event.replaceInput({ mod: 'somemod', ... })` —— 材料收束**必须带 `mod` 过滤**，只作用于该模组配方；原版配方在政策【待定】落地前一律不碰。逐模组处理，不做全局替换。
3. `ItemEvents.modification` —— 调整模组武器**原版模式**下的基础攻击力，作为 EF 模式判定之外的兜底；EF 模式下的动作与判定数值由 capability JSON 决定（见 §6），两者互不替代。

注意事项：

- 【注意】示例中的 `kubejs:refined_iron_ingot`（精制铁锭）在方案 3.4 的注册示例中**并未注册**——这是方案 3.3 与 3.4 之间的缺口。落地时二选一：在 `startup_scripts/` 补注册该物品，或改用已注册的 `kubejs:tempered_steel_billet`。属武器线设计决策，走工作流 P13（S 级）拍板后再写。
- `item.attackDamage` 为物品属性层面的修改，不影响 EF 模式由动画驱动的伤害判定；手感必须进游戏实测，数值表不代表体验。

验收清单：

- [ ] `/reload` 无报错
- [ ] 被移除配方的物品在 JEI 中不再显示原合成途径，且任务 / 战利品投放已就位
- [ ] 材料收束只影响目标模组配方，抽查原版配方原样未动
- [ ] 被改数值的武器在原版模式与 EF 模式下分别实测

## 3. 自定义物品注册（方案 3.4）

文件：`kubejs/startup_scripts/items.js`（**需重启生效**）

作用：注册本包独占的战斗向物品，支撑「Boss 掉落材料 → 中间产物 → 终局武器材料」的主线锻造线。

```javascript
// startup_scripts/items.js：注册本包独占的战斗向物品（需重启生效）
StartupEvents.registry('item', event => {
  // 终局武器材料：由 Cataclysm 等 Boss 掉落物合成的顶级锻造材料
  event.create('abyss_ingot').maxStackSize(16).glow(true).rarity('epic')
  // 中间产物：下界/暮色 Boss 素材的初步锻造件
  event.create('tempered_steel_billet').maxStackSize(32).rarity('uncommon')
  // 任务/纪念向物品：终局武器的"破损前身"，用于任务线叙事
  event.create('broken_hero_blade').maxStackSize(1).rarity('rare')
})
```

说明：

- 三件物品均注册在 `kubejs:` 命名空间下，全仓引用 ID 为 `kubejs:abyss_ingot` 等。
- 配套配方（Boss 掉落物 → 中间产物 → 终局材料）在 `server_scripts/` 用 `event.shaped` / `event.shapeless` 串联；不希望玩家过早看到的终局配方用 `client_scripts/` 的 JEI 隐藏，并与 §4 阶段门控配合。
- 任务奖励遵循「材料 > 成品」原则：多发 `tempered_steel_billet` 等中间产物，少发成品武器，把成就感留在锻造环节。

验收清单：

- [ ] 重启游戏后 `/give` 三件物品均成功
- [ ] JEI 中可见，稀有度 / 发光 / 堆叠上限正确
- [ ] 后续配方与任务引用的 ID 与此完全一致

## 4. 五阶段门控脚本（方案 3.5）

文件：`scripts/stages.zs`（CraftTweaker，`/reload` 生效）

作用：GameStages 以按玩家存储的布尔标志记录阶段（`/gamestage add @p <阶段名>` 授予），实际锁定由附属执行——本示例用 RecipeStages 把终局锻造材料锁进「终局」阶段。**原版配方一律不进门控。**

```zenscript
// scripts/stages.zs：把终局锻造材料锁进"终局"阶段（原版配方一律不进门控）
mods.recipestages.Recipes.addRecipeStage("endgame", <item:kubejs:abyss_ingot>);
```

五阶段体系摘要（详见方案 3.5 门控表）：

| 阶段 | 里程碑 | 关键解锁 |
|---|---|---|
| Ⅰ 启程 | 进入世界（默认） | EF 序章教学、共生体坠星事件；原版装备线不锁 |
| Ⅱ 深入下界 | 首次进入下界 | 圣龙驯龙解锁、御剑技能书发放启动 |
| Ⅲ 暮色森林 | 击败凋灵 | 暮色维度开放、淬魔钢坯配方、TiC 高阶武器材料 |
| Ⅳ 真菌天灾升级 | 击败暮色主线 Boss | Mound 活跃化、Calamity 级 Boss 解锁 |
| Ⅴ 终局 | 共生体 Dominant + 首个 Calamity 讨伐 | abyss_ingot 终局锻造、共生体终局能力 |

配套机制：

- **阶段授予**：FTB Quests 里程碑任务的命令奖励执行 `/gamestage add @p <阶段名>`，形成「击败 Boss / 天灾升级 → 完成任务 → 解锁下一阶段」闭环；
- **维度门控**：暮色森林在阶段授予前由 DimensionStages 拦截进入；
- **天灾烈度切换**：阶段授予任务联动 sporeconfig 三档与 In Control! 规则（见 §8.1）。

待核实：`<item:...>` 写法与 CrT 14.0.x 的 RecipeStages 实际 API 以现场 `/ct hand` 与 CrT 日志为准；建议用低阶段测试账号验证锁定效果。

验收清单：

- [ ] `/reload` 后 CraftTweaker 日志无报错
- [ ] 未授予阶段时，目标配方对玩家不可用（表现以 RecipeStages 实际行为为准）
- [ ] 授予阶段后可正常合成
- [ ] **原版配方全程不受影响**（抽查木 / 石 / 铁 / 钻石 / 下界合金线）

## 5. 探索痛点改造脚本（方案 3.7）

文件：`kubejs/server_scripts/explorers_compass.js`（`/reload` 热重载）

作用：把 Explorer's Compass 从「中前期定位器」改造为「高成本中后期兜底」，并限制跨维度使用——它只能缩短无效跑图，不能替代亲自探索。

```javascript
// server_scripts/explorers_compass.js：指南针配方便携化改造
ServerEvents.recipes(event => {
  event.remove({ output: 'explorerscompass:explorerscompass' })
  event.shaped('explorerscompass:explorerscompass', ['NDN', 'DCD', 'NDN'], {
    N: 'minecraft:netherite_ingot',
    D: 'kubejs:tempered_steel_billet',
    C: 'minecraft:compass'
  })
})

// 限制使用维度：仅主世界与暮色森林可定位结构
ItemEvents.rightClicked('explorerscompass:explorerscompass', event => {
  let dim = event.level.dimension.toString()
  if (dim != 'minecraft:overworld' && dim != 'twilightforest:twilight_forest') {
    event.player.tell('§c指南针的魔力在这片空间紊乱，无法定位结构……')
    event.cancel()
  }
})
```

逐段解释：

1. 配方重写：改为下界合金 ×4 + `tempered_steel_billet` ×4 + 指南针，成本对齐「中后期奖励」定位；
2. 维度限制：右键事件中判断当前维度，非主世界 / 暮色森林时提示并取消使用，防跨维度抄近路。

配套改造（脚本之外的 config / 模组层，均出自方案 3.7）：

- **Xaero's 地图**：经 `defaultconfigs/` 或 Default Options 下发关闭传送的配置；服务端用 Minimap Server Settings（25.3.0+）按权限组强制关闭洞穴模式与实体雷达，可配合药水 `xaerominimap:no_entity_radars` / `no_cave_maps` / `no_waypoints`（效果 ID 以游戏内实测为准）；单人存档还需在路径点菜单按世界关闭传送（传送本质是代发 `/tp`，服务端不给 tp 权限即失效）；
- **Explorer's Compass config**：调低 `maxRadius` / `maxSamples`、配置结构黑名单（支持通配符，屏蔽 Boss 竞技场等高价值结构）；若采用 Enhance 分支可另关 `allowTeleport`【待核实是否收录该分支】；
- **Waystones**：必须亲自激活石碑方可互传；参考 RLCraft 收取 XP（≤1000 格免费，之后每 1000 格 1 级，跨维度 3 级），并禁用 Sharestone / Portstone / Warp Plate 等廉价变体（键名以模组 config 实际生成为准【待核实】）；
- **替代引导**：Fast Travel Waypoints（只能传到已激活石碑）、Antique Atlas 4（发现才标注）、FTB Quests 勘察任务（奖励回程手段）、RoadWeaver 道路网（沿路自然抵达村庄与结构）。

待核实：

- 【注意】`event.level.dimension.toString()` 的返回值形态：KubeJS 中 `dimension` 可能返回 `ResourceKey` 包装对象，直接与 `'minecraft:overworld'` 比较可能恒为 false。落地时先在游戏内打印实际值确认，必要时改用 `.location()` 后比较；
- 暮色维度 ID `twilightforest:twilight_forest` 以 F3 实测为准。

验收清单：

- [ ] 合成表为新配方，材料与成本正确
- [ ] 主世界 / 暮色森林内可正常搜索结构
- [ ] 下界 / 末地右键被拦截且显示提示
- [ ] Xaero's 路径点传送不可用（单人与服务端各测一次），实体雷达已关闭
- [ ] Waystones 未激活石碑不可传送、激活后按距离扣 XP

## 6. Epic Fight 武器适配 capability JSON（方案 3.8）

路径规则：`data/<物品所属modid>/capabilities/weapons/<物品注册名>.json`，落位到 `kubejs/data/`（KubeJS 数据包）或 `config/openloader/data/`（Open Loader 全局加载）任一通道（生效方式见 §1）。

作用：让未适配 EF 的第三方武器获得 EF 武器类型与战斗属性。全包适配优先级：**CompatLink 配置 > EFMCompat 现成补丁 > 本 JSON > EF API 自建**——先用现成补丁，JSON 只补缺口。

示例（Cataclysm 的 Boss 武器「焚化者」适配为 EF 巨剑类型）：

```json
// data/cataclysm/capabilities/weapons/the_incinerator.json
// 将 Cataclysm 的 Boss 武器"焚化者"适配为 EF 巨剑类型
{
  "type": "epicfight:greatsword",
  "attributes": {
    "armor_negation": 20.0,
    "impact": 3.0,
    "max_strikes": 3
  }
}
```

字段解释：

| 字段 | 含义 |
|---|---|
| `type` | EF 动作类型：16 种内置类型（如 `epicfight:greatsword` 巨剑、`epicfight:katana` 太刀）或附属新增类型（如 `wom:ruine`）；其余前缀一律列入待核实清单 |
| `armor_negation` | 护甲穿透（%），越高越无视目标护甲 |
| `impact` | 冲击力 / 削韧，影响对目标的硬直 |
| `max_strikes` | 单次挥击命中目标数 |

盔甲适配：文件放 `capabilities/armors/<注册名>.json`，字段为 `stun_armor`（抗击退 / 霸体值）与 `weight`（重量，影响闪避与体力）。盔甲模型弯曲 / 渲染问题优先用 CompatLink 渲染修复或官方 Custom 3D Armor Resource Pack 指南处理。

纪律与流程（对齐工作流 P4 / P5 与工程红线）：

1. 先由「适配矩阵 CSV」（modid:item_id | 所属武器线 | 流程节点 | 内容带 | 动作类型 | 三属性 | 依据）人工 `/kubejs hand` 核实 ID 并回填；
2. 批量生成 → `python scripts/check_json.py` 语法校验（脚本由仓库脚手架任务提供）→ 抽检 10% → 入库；
3. 三属性数值严格取自 3.3 武器线标准值表，与「入门 → 进阶 → 大成」节点对档，不得自行调整；
4. **进游戏实测**：EF 伤害判定由动画驱动、武器碰撞体相交才结算——数值表不代表手感，逐把验证动作衔接、攻击范围与硬直表现。

验收清单（每批）：

- [ ] JSON 语法校验全绿
- [ ] 游戏内武器在 EF 战斗模式下出现对应动作类型
- [ ] 三属性与 CSV 一致
- [ ] 无「装了 JSON 反而丢失原默认行为」的回归

## 7. Default Options 键位下发（方案 3.9①）

作用：解决 Symbiote 与 Epic Fight 的 R / K 撞键——EF 默认 R=战斗模式切换、K=技能编辑菜单，Symbiote 默认 R=触须猛拉、K=掠食者形态。方案：**Symbiote 改绑 V=触须猛拉、B=掠食者形态，EF 键位保持默认**（降低玩家学习成本）。

通道：Default Options 模组下发预调好的 `options.txt` 与各模组键位配置，作为**新建存档默认值**——与 Xaero's 配置下发同一通道。

配套：任务序章「觉醒」以图文说明最终键位表；劫持机制调频走 Symbiote config（下调压力积累速度、上调劫持触发阈值，使劫持成为「疏于养成的惩罚」——具体键名以模组 config 实际生成为准【待核实】）。

验收清单：

- [ ] 新建存档首次启动，键位即为下发值
- [ ] EF 战斗模式与触须猛拉 / 掠食者形态互不吞输入【需实测】
- [ ] 共生体高压劫持触发时与 EF 战斗模式可叠加、不长期打断节奏【需实测】
- [ ] 老存档键位不被覆盖（Default Options 只影响新建存档）

## 8. 配套机制说明（config 层，简述）

### 8.1 sporeconfig 三档调参（红线）

真菌天灾烈度曲线化为三档：**压制档（阶段Ⅱ–Ⅲ 默认）→ 活跃化档（阶段Ⅳ Mound 放开）→ 终局档（阶段Ⅴ Calamity 全开）**。

- 三档具体键值由 S 级任务 P8（glm5.3）产出，本文不载具体参数（红线任务不降级，R6）；
- Spore 每次升级**删除旧 config 重新生成**再回填调参，避免残留键值引发行为漂移；升级后进档回归实测扩散速率；
- 感染按方块 tick，是全包最大 TPS 消耗源——标配 Canary + spark 持续监控；
- 配套：Spore Inquisition 数据包（感染改定点 Mound 坠落制）、In Control! 维度隔离（规则文件置于模组配置目录，字段名以模组文档为准【待核实】）、CDU 部署教学任务线、定期自动备份（腐蚀不可逆）。

### 8.2 圣龙传说群系标签注入

用数据包把 `saintsdragons:has_<dragon>` 系列标签追加到 Terralith 群系（在 `data/<标签命名空间>/tags/worldgen/biome/<标签名>.json` 中列出 `terralith:*` 群系 ID；数据包标签默认与模组内置标签合并；**具体标签名以模组 jar 内 tags 文件为准**【待核实】）。效果：龙按地貌分布，想要某种龙就得去对应群系跑图，与探索引导线咬合。

必装前置：GeckoLib 4.8.1+ 与 **Mount Fix**（修复 EF 骑乘本模组龙时的崩溃）。骑乘限定赶路用途，野生龙属性对齐阶段Ⅱ 威胁曲线；Alpha 存档定时备份。
