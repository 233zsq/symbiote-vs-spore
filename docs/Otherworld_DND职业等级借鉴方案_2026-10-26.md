# Otherworld研究与SvS的DND职业等级方案

> **2026-10-31本批状态：** 本研究保留13职业／44子职业的参考证据；当前已确认计划收敛为等级成长／GameStages、加点和少量子职业能力，不实施文中完整13职业方案，不安装Origins／Apotheosis／TravelOptics。详见[采纳对照](DeepSeek建议_采纳对照_2026-10-31.md)及[后续计划](剧情与FTB施工计划_2026-10-31.md)。

以下保留原采样／研究正文，数量与“当前”按各自日期阅读；本批结果以上述记录为准。
2026-10-26。用户希望借鉴DND的职业与等级规则，本轮研究本地Otherworld并提出适配SvS的方案。**方案没有实施，未安装职业模组，未改变既有机制、剧情或FTB。** 本文的“参考包实况”和“SvS建议”分开列出，不能把建议写回已批决议。

## 1. 结论

最值得借鉴的是：职业具有不同战斗职责，等级定期解锁选择，子职业改变打法，专长补足构筑，休息恢复有限资源，任务为成长提供目标。建议把SvS做成**DND职业成长 + 现有EF即时动作战斗**，不把实时挥刀改为掷骰命中。

不建议整套复制Otherworld的定制核心。它实际使用Better Combat，并通过Origins、Just Leveling Fork、Otherworld Core和大量跨模组适配共同工作。直接加入几个同名JAR，会同时带入属性、施法限制、附魔限制、耐久和升级门槛，成本远大于“加一个职业选择界面”。

推荐用现有EF、Iron's Spells、FTB和小型职业适配模块实现SvS自己的规则；现有Epic Fight Skill Tree可以研究用于显示/分发战斗技能，但本轮未证明它原生支持完整职业条件，不能预先承诺仅靠它完成。

## 2. Otherworld实际由什么组成

研究目录：`C:/PCL 正式版 2.8.13/.minecraft/versions/Otherworld`，400个顶层JAR，只读。

| 组件 | 本地版本 | 在该包中的作用及限制 |
|---|---|---|
| Otherworld Origins | 2.0.1 | 职业/种族/子职业/专长、能力资源、法术与附魔限制；强依赖Otherworld Core、JLF、Origins、Apotheosis、Iron's Spells、TravelOptics |
| Otherworld Core | `otherworld-0.8.5+1.20.1.jar` | 角色等级换算、事件与UI同步、章节升级限制、篝火恢复、结构再生及跨模组修正 |
| Origins Forge | 1.10.0.9 | 分层角色选择和能力框架，配套Apoli/Calio |
| Just Leveling Fork | 1.2.1 | 八项aptitude、消耗经验加点、属性/被动与UI，客户端需YACL |
| Auto Leveling | 1.20-1.19b | 怪物等级与属性倍率，不是玩家职业等级 |
| Otherworld Apoth | 0.7.2 | 整合包专属Apotheosis调整 |
| Better Combat | 1.9.0 | 该包即时战斗底座，与SvS的EF不同 |

Otherworld Core还强依赖BOMD、Aether Villages和严格版本`TravelOptics [6.3.0,6.3.1)`，Forge至少47.4.12。满足Forge版本不等于满足整条依赖链。定制核心/Origins附属/Apoth元数据为ARR；不能默认复制或修改其内部实现用于公开分发。JLF与Origins本身有开放许可，也不能消除定制部分的耦合。

## 3. 角色等级和加点：不要把80误读成角色80级

当前有效配置位于`config/JLFork/justleveling-fork.common.json5`和`justleveling-fork.lockItems.json5`。根目录旧`just_leveling-common.toml`明确废弃，不用它推断当前规则。

- 单项aptitude上限20；全局加点和上限80；首级费用参数15。
- 八项aptitude是力量、体质、敏捷、防御、智力、建造、魔法、幸运，**不是DND标准六属性**。
- 原生JLF升级成本按该项当前等级和首级费用参数计算原版经验点；不是只到某个总经验等级就自动提升DND角色等级。
- `LevelingUtils.getPlayerLevel`把加点和换算为角色等级；Otherworld Origins的Mixin先扣除种族/职业等先天aptitude加值。

正常基线范围的公式为：`角色等级 = min(20, 2 + Java整数除法((G - 8), 4))`，其中G为扣除先天加值后的全局点数。示例：G=8对应2级，12对应3级，80对应20级；代码不是简单的“总点数÷4”。这些是静态算法，不是读取某玩家存档后的等级结论。

Core还含`StoryProgressionRestriction`：若GameStages存在，角色到6、9、12、15、18级后，继续升级分别要求`chapter_1`～`chapter_5`。缺少GameStages或反射出错时会放行。它将刷经验成长接回章节进度，这个设计可以借鉴，**对应stage字符串和五章阈值不能复制到SvS的四阶段**。

有效lockItemList为空，故不能宣称这份包已启用JLF的装备等级锁；原JAR默认锁物清单不代表整合包当前配置。

## 4. 职业、子职业、专长与恢复

从原生origin JSON核实13个职业、44个子职业，分布如下。这里的能力举例来自实际power资源，并非纯DND规则书描述。

| 职业 | 子职业数 | 已核实的能力方向 |
|---|---:|---|
| 奇械师 Artificer | 4 | 修理惩罚、工艺与soul_of_artifice |
| 野蛮人 Barbarian | 3 | rage狂暴 |
| 吟游诗人 Bard | 3 | inspiration激励、戏法 |
| 牧师 Cleric | 5 | 职业属性、神术/戏法与子职业 |
| 德鲁伊 Druid | 3 | wildshape野性变形 |
| 战士 Fighter | 3 | second_wind再振作 |
| 武僧 Monk | 3 | ki气、步法、偏转飞弹 |
| 圣武士 Paladin | 4 | lay_on_hands圣疗 |
| 游侠 Ranger | 3 | favored_foe、goodberry、landstride |
| 游荡者 Rogue | 3 | sneak_attack、uncanny_dodge |
| 术士 Sorcerer | 2 | 职业施法与血脉分支 |
| 邪术师 Warlock | 2 | eldritch_blast魔能爆与契约分支 |
| 法师 Wizard | 6 | 职业施法、学派分支 |

角色选择分成种族、亚种、职业、子职业、戏法、专长等layer。标准专长选择在4、8、12、16、20级开放，每层有条件筛选，不应把五层重复列表相加成五倍的独立专长。变体人另有free_feat；德鲁伊变形按2/4/6/8级逐步开放，月之环有额外形态，10级有元素选项。子职业layer本身没有统一的角色等级门槛，不要宣称该包所有职业都在3级才选择子职业。

资源恢复也不是统一照搬桌游：武僧气在睡醒和升级时补充；战士再振作为600tick冷却；不同职业有不同资源与触发。Core另有篝火恢复，当前配置参数为半径5、检查间隔40tick、离战5秒；代码区分普通点燃营火回血0.5与Ambrosium营火回蓝2，并非任意营火同时恢复两者。`enableAutoRegeneration`控制的是结构自动再生，**不是玩家自动回血**，不要拿它当“长休开关”。

`spellRestrictions.enabled=true`时，允许施放的法术取决于能力与法术标签，另有不受限标签；`config/otherworldorigins/spells.json`是法术目录信息，不能把它当作最终职业许可表。附魔也有职业限制，例如经验修补绑定奇械师。SvS若直接引入，现有装备、技能书与附魔经济都会受到影响。

## 5. 怪物等级是另一套系统

当前AutoLeveling配置：起始1、最高20，距出生每格增加0.001，海平面下深度每格增加0.05；随机和天数加成为0。普通路径按`bonus × 内部等级`创建`MULTIPLY_TOTAL`属性修饰器：攻击、护甲、血量、法术抗性等配置0.2，表示线性增加倍率，不是每级递乘1.2的指数增长。

Core又支持按实体覆盖属性修饰器并取消部分被动生物等级；显示等级与内部等级也有换算。上述默认公式不等于每个Boss的最终强度。结构等级加成当前关闭。SvS已有难度三档、共生成长、Boss原生属性与炮塔，不能再无差别叠加一套距离血量倍率。

建议只借鉴等级提示与区域威胁分级：Boss用人工确定的推荐等级/能力需求，普通怪再单独评估有限成长。先算组合预算再决定是否装AutoLeveling，不将其作为DND职业的必需前置。

## 6. SvS规则草案：角色层与专精层分开

以下为本轮建议，尚未成为当前规则。

角色资料建议包括：个人UUID、规则版本、角色等级1～20、六属性、一个战斗职业、一个子职业、专长、熟练项、有限职业资源与已领取成长记录。原版经验条继续用于附魔/修理；真菌残魂继续承担经济用途；EF体力、现有法力与共生体成长各司其职。

原有收藏家/锻造师/狩龙人/共生使更适合改称成长专精或职业支线，与战斗职业分层。例如“战士＋锻造师”“游侠＋狩龙人”“邪术师＋共生使”都成立。四支线内容和既有奖励不能在迁移时清空；收藏家与军械全鉴保持合并及T2/T1/T0鉴定方向。

| 规则 | 推荐草案 | 对SvS的实际意义 |
|---|---|---|
| 六属性 | 力量/敏捷/体质/智力/感知/魅力；固定标准数组15/14/13/12/10/8，后续可选点购 | 开局可解释、可重现，避免随机掷出高属性强迫重开 |
| 属性修正 | `floor((属性-10)/2)`作为角色规则输入 | 不直接把修正值等量加到攻击/护甲；先与现有属性预算换算 |
| 熟练加值 | 1～4级+2、5～8级+3、9～12级+4、13～16级+5、17～20级+6 | 用于职业检定、熟练效果与解锁，不给每次挥刀增加随机落空 |
| 等级来源 | 章节/探索/职业挑战的一次性成长为主，可重复活动补充且有限额 | 防止刷怪塔、反复领奖和高经验物品直接跳过成长 |
| 成长节奏 | 1级定职业；3级选子职业；4/8/12/16/19级选择属性成长或专长；20级职业终阶 | 这是SvS草案，19级不是Otherworld五专长层的原样复制 |
| 即时动作战斗 | EF负责命中、格挡、闪避、连段和体力 | DND职责影响打法，保留现有动作品质 |
| 装备熟练 | 使用擅长装备获得职业技/效率收益，非擅长仍可装备与收藏 | 不恢复此前否决的全局武器解锁门禁，不让T0奖励变成拿到不能用 |
| 休息 | 营地短休恢复部分职业资源，安全据点长休恢复完整资源；有战斗和时间条件 | 与篝火、火种/营地交互建立玩法联系，不能用死亡/切世界无限补满 |
| 法术 | 首版保留现有法力；职业资源控制特色技，大法术再研究每日次数 | 避免同时增加法力、体力、法术位、气等多条重复消耗 |
| 多职业 | 首版单职业，可付费/限次洗职业，后续再研究兼职 | 先证明每个职业能独立玩，再处理跨职业数值组合 |

等级推荐区间可映射四阶段为1～5、6～10、11～15、16～20，但本轮不绑定剧情节点。采用“成长上限随阶段开放、溢出进度保留”的方案需要新裁决；默认方案先做推荐等级与一次性成长，**不锁下界/末地门，也不要求全收藏毕业**。

## 7. 13职业如何适配现有内容

目标可以保留完整13职业。下面是SvS的职责建议，不是声称这些效果已被某个模组提供；首个实现原型先用战士、游侠、法师验证近战/远程/施法三条通路，再扩展全职业。

| 职业 | SvS职责与特色 | 可接现有内容 | 首版边界 |
|---|---|---|---|
| 战士 | 连段、格挡后反击、有限再振作 | EF武器/技能书、军械鉴定 | 不自动发全套顶阶技能 |
| 野蛮人 | 狂暴与高风险近身压制 | 重武器、体力/受击反馈 | 不叠无限减伤和永久霸体 |
| 圣武士 | 近战圣击、护队与有限圣疗 | 近战武器、保留的支援法术 | 不能靠全程无敌替代格挡 |
| 游侠 | 远程狩猎、标记目标、伙伴协同 | 弓弩、追踪、狩龙内容 | 必须先解决地面Boss远程免疫裁决 |
| 游荡者 | 位移、背袭、利用破绽 | 匕首/轻武器、机动法术 | 偷袭有窗口和内置冷却，多段连击不重复触发 |
| 武僧 | 体力管理、短打与偏转 | EF徒手/拳套可用性需核实 | 无可用武器动作前不宣布职业完成 |
| 法师 | 可选学派、法术研究与控制 | 铁魔法现有保留36项 | 不自动恢复被禁78项 |
| 术士 | 血脉与有限超魔强化 | 现有法术属性与施法通路 | 与法师有操作差别，不能只换伤害颜色 |
| 邪术师 | 契约、短休资源与代价换取 | 共生体主题、诅咒/魔能方向 | 共生使是可组合专精，不强制绑定该职业 |
| 牧师 | 治疗、净化与支援 | 保留的治疗/增益、火种保护 | 单人也有合理输出，治疗不直接抹平围城惩罚 |
| 德鲁伊 | 自然控制、恢复、动物协同 | 自然材料与已有动物 | 先做自然施法；变形涉及EF模型/体型，作为独立技术项 |
| 吟游诗人 | 队伍激励、弱化与机动支援 | 饰品、有限增益和任务奖励 | 单人有自用收益，光环同类不叠加 |
| 奇械师 | 装置、修理与军工作战 | 匠魂、炮塔、锻造材料 | 炮塔击杀归因/个人归属要接入；不独占所有玩家的基础修理 |

奖励建议分工：等级发职业选择和少量能力；主线发关键资源与装备机会；军械鉴定给残魂、材料和分档奖池；挑战发特色技能书/饰品。不得把技能书同时作为自动升级赠品、任务奖励和商店无限购而不计重复价值。具体物品ID与数值要等目标模组列表稳定后逐件登记。

## 8. 必须明确的新旧规则冲突

| 问题 | 当前有效规则 | 本轮推荐的新方向，未实施 |
|---|---|---|
| 游侠/攻击法师如何打地面Boss | 现有脚本对指定地面Boss远程归零；飞行/水中另算 | 如果要让DND远程职业完整成立，建议改为按Boss/阶段设远程系数或反制窗口，移除一刀切免疫；这是实质规则变更 |
| 职业与剑术耗蓝 | EFS-ISS已负责剑术耗蓝 | 保留一条法力账本，职业资源只给特色技；逐项验证消耗与恢复，不能双扣或绕开 |
| 职业选法术 | 铁魔法禁78留36 | 先在保留集合内分配，名单不足的职业另做技能，而非悄悄全放开 |
| 职业等级与Super-Tier | 后者读取原版经验等级减免消耗 | 不共享数值；若加入需单独改成本策略，否则会绕开职业成长 |
| 职业与T0收藏 | 鉴定、装备/技能/饰品分档奖励 | 所有职业都能收集，熟练给使用收益，不把收藏品发放重新变门禁 |
| 个人角色与队伍FTB | 主线有队伍共享进度 | 角色选择、专长、资源和领奖账本必须个人保存；团队完成只触发个人待领，不直接批量改职业 |
| 成长与难度倍率 | 三档难度和Boss/共生体机制已存在 | 首版避免同时开启AutoLeveling全局倍率；先测裸装/常用装/顶装三档预算 |

当前旧规则继续运行；本表为未来实施前的设计选择，不因为写了方案就替用户改定。

## 9. 实现路线比较

| 路线 | 优点 | 代价/结论 |
|---|---|---|
| 整套移植Otherworld Origins/Core | 已有职业界面与大量现成功能 | 强依赖与特定版本、Better Combat适配、定制许可、额外机制；不推荐 |
| Origins Forge + 自己的数据与小型适配层 | 分层选择、能力与资源框架成熟 | 仍需验证Apoli/EF、视角、法术和同步；可作为备选，不能只复制44子职业JSON |
| JLF + 自己职业系统 | 已有加点UI与经验消费 | 原生八项属性不等于六属性，战斗属性叠加和装备锁需重配；若保留八项成长才值得采用 |
| 现有栈 + SvS轻量职业模块 | 保留EF、法力、既有经济与任务桥；能按六属性设计 | 需开发个人数据、选择UI、技能事件与迁移；本轮推荐 |

推荐模块以数据定义职业、等级表、专长和技能许可，服务端保存个人状态并校验选择；HUD/角色页展示职业、等级、下次解锁。FTB负责教程和一次性发放入口，不作为唯一数据存储。固定UUID的属性修饰器可替换/撤销，洗点后先清理再重建；技能使用走现有伤害与归因通路；不修改EF或ARR模组JAR。

## 10. 后续可执行工作包

1. 确定职业版规则：六属性、等级来源、远程Boss策略、休息/法力关系、是否阶段上限。以本报告推荐值做可审阅规格，不先动现有游戏。
2. 离线原型：三职业、1～5级、一个专长/子职业样例；证明个人保存、退出重进、死亡、重置职业、重复领奖不丢状态也不叠属性。
